# FE Maker architecture

One line per module: what it does, where its data lives, what to watch out for. Rules and working habits are in `CLAUDE.md`, pitfalls in `docs/pieges.md`.

## Server

- `server/fe_maker/migrations.py`: projects across versions, run by `Project.__init__`: `formatVersion` read, a newer project refused (`ProjectTooNew`), `data/` copied to `backups/` then `MIGRATIONS` run in order, restored if one fails. A renamed or moved field adds a step; a field that is only new goes in `FIELDS_ADDED_LATER`. Format 2: allies' levels moved to their sheets. `tests/server/fixtures/project-v1` is a format 1 project every version must open: never edit it to make a test pass.
- `server/fe_maker/ferepo.py`: FE-Repo browser (index `file_urls.json` and downloaded files cached in the user's config dir `ferepo/`; licence and authors read from file names; `Project.update_credits`, also run at each build, writes them to the project's CREDITS.txt, with the `AI_NOTE` disclosure). Tests mock `_download`: never download from tests. Battle animations are folders in its index (GitHub "tree" URLs): their files come from GitHub's contents API (60 requests an hour without an account, listings cached in `ferepo/folders/`); their weapons, for the library's weapon filter, come from one git tree request per top folder (`animation_weapons`, cached a week in `ferepo/weapons/`). Downloads use certifi's certificates (Windows' store failed on api.github.com, 29/10/2026).
- `server/fe_maker/scope.py`: what a project keeps of the game (ticket 71, Game options tab, `/api/project/scope`): records leave the project's lists only, chapters become free slots (`newchapter.drop_chapters`), `data/` is copied to `backups/` first.
- `server/fe_maker/newchapter.py`: chapters the project adds take a free slot (own map and event group, not reached by the story: tower, ruins, debug chapters), cleared with project data only (titles, empty map, emptied groups, the army of the chapter before, simple opening, story links); chapters.json "added" / "titles"; `POST /api/chapters/new`. Blank project (`start_blank`, `POST /api/projects` with `blank`): chapter 0 cleared, chapters.json `blank` (the game's chapters are free slots and `hidden` in the editors), `blankCharacters` (all named characters but the first lord and `NAMED_GENERICS` out of the list, `DecompData.blank_dropped_characters`; `reusable_characters` are reused by `new_character(reuse=True)`; older projects tidied at opening, `tidy_blank`), `cleared` (event lists emptied at build by `objectives.clear_events`).
- `server/fe_maker/__main__.py`: a launch while FE Maker runs restarts it (`POST /api/shutdown`, refused with 409 during a build; an older server without it is killed by the PID listening on the port, Windows only). My own server on 8765 is replaced too when the user clicks the shortcut.
- Ticket relay: `relay/` (Cloudflare Worker `fe-maker-tickets`, plain JS, `node --test`): tickets become issues of the private `fe-maker-feedback` repository (screenshots and project in `uploads/`), a SHA-256 of each ticket's secret in the issue body; `tickets.py` sends (`send`, `relay_call`, FE_MAKER_RELAY=off in tests), reads back (`sync`), `--remote` lists the issues with `gh`.
- File menu: `FileMenu.svelte`, opened by the app's name at the left of the top bar (`App.svelte`), office-style: commands on the left (new, open, save, save as, rename, folder, export, close, options, help, quit), a pane on the right (recent projects, options, help). It acts on the open project through `ui/src/lib/filemenu.svelte.ts` (`fileMenu.project`, filled by `Workspace.svelte` while it is mounted); Quit flushes and calls `/api/shutdown`. `App.svelte` keys `Workspace` on the project path, so opening another project from the menu remounts it. Languages stay as flags at the top right. Its Options… command opens `OptionsDialog.svelte`, a window with categories on the left (Emulator: keys, mGBA settings from `emulator.MGBA_OPTIONS` — `Settings.mgba_options`, checked by `validate_options`, written by `write_options` at each launch, a setting never set left to mGBA — and mGBA's sound for tests (`Settings.volume` / `mute`, written to `[ports.qt]` of mGBA's config.ini by `emulator.write_sound` at each launch; volume None leaves mGBA's own; This project: `ProjectSettings.svelte` (the open project's FE Maker settings: show original, test start, simplified prologue; moved out of the game options). Folder picker: `server/fe_maker/folderpick.py` opens the system's dialog with tkinter on the server's machine (`/api/pick-folder`, 501 `pickerUnavailable` without Tk), used by `FolderPickButton.svelte` (open a project, new project's folder, save as; `ui/src/lib/paths.ts` names the new folder after the project).
- Feedback tickets: `server/fe_maker/tickets.py` (stored in the user's config dir, `tickets/tickets.json` + `images/`, never in the repo; a ticket's replies are `comments`, printed with it), `TicketPanel.svelte` (side column opened by the header button), `ui/src/lib/appContext.svelte.ts` (tab / record / detail attached to a ticket; `RecordList` and `ChapterEditor` fill it). List open tickets with `python -m fe_maker.tickets`. Admin mode (the testers' tickets): `admin_*` in tickets.py run the `gh` CLI with the admin's own login (no token in FE Maker), `/api/admin/*`, shown as a "Testeurs" view of the panel only when `gh` may write to the feedback repository; admin replies are plain comments (the relay hands them back), screenshots read through `/api/admin/file`.

## Reading and writing the decomp

`server/fe_maker/decomp/`, one module per subject.

- Items' sheet (`gamedata.py`): `properties` are attribute flags (`ITEM_PROPERTIES`), IA_WEAPON and IA_STAFF follow the type (`_type_flags`), the UI ticks `magic` with the type; `statBonuses` changed by the project are `ItemBonus_FEM_<item>`, written above `gItemData` (`_with_item_bonuses`); `spellFrom` copies another item's row of the spell table (`_with_spell_choices`, after `_with_new_item_copies`); `useDescription` gets its own message when the game's is shared.
- `gamedata.py`: characters, items, classes, combat, chapters; apply order classes → characters → items → combat → chapters. chapters.json `levelBonus` by chapter: the game's difficulty levels (`LEVEL_BONUS_FIELDS`). New characters take a free entry of the full table (`free_character_numbers`: raw-numbered, loaded by no unit): id `CHARACTER_NEW_<hex>`, constant added to `characters.h` at build time, own name text; allies below 0x46 (`BWL_ARRAY_NUM`), enemies above; `POST /api/characters/new`. New items (`ITEM_NEW_<hex>`, after the game's last item up to 0xFE) copy a model item's fields (weapon, staff, monster weapon, consumable), its `spellassoc-data.c` line and its item-specific `data_banimconf.c` entries (`_with_new_item_copies`); the engine acts by item number, so `_copy_item_behaviour` adds the copy to each `case ITEM_X:`, `== ITEM_X` / `!= ITEM_X` and AI table row `{ ITEM_X, ... }` of the model in `src/*.c` (ticket 144); `actsLike` takes another game item's effect instead of the model's; `effectAmount` gives a healing copy or a Pure Water copy its own case with its own amount (`_own_item_amount`); `tempBonuses` (`temp_bonuses()`, which also reads the older `effectStat`/`effectAmount`) gives a Pure Water copy bonuses or maluses on several stats that fade each turn: one signed 4-bit counter per stat, -8..+7 (`TEMP_STATS`, Resistance included; a getter result stops at 0, `TempStatFem`; a drink goes through `TempBonusesAfterFem`, whose rule `TEMP_BONUS_RULE_FEM` is the game option `tempBonusRule`, `gameoptions.CHOICES`, the first kind of option with several choices; the status screen draws a malus, fontgrp.c and statscreen.c) in the unit's spare bytes `_u3A`, `_u3B`, `_u47` (macros `TEMP_BONUS_FEM` added to bmunit.h), read by the `GetUnit<Stat>` getters, lowered in `TickActiveFactionTurn`, cleared in bmio.c, kept across a suspend in the save memory's unused bytes 0x73A4-0x7400 (`TEMP_BONUS_SAVE`, 46 bytes per suspend slot, up to 10 units, tied to the save time) (`_with_temporary_bonus`); `POST /api/items/new`. New classes (`CLASS_NEW_<hex>`, 0x80-0xFE, keyed `[CLASS_NEW_80 - 1]` like the game's) copy a model class, add rows to `unit_icon_move_table` (one per class, in order) and a `gPromoJidLut` row for the last one; the API shows a new class's sprites and animations from its model (`_game_class`).
- `cparse.py`: designated-initializer parser.
- `combat.py`: weapon triangle and effectiveness; `read_affinity_bonuses` (shown by `AffinityPicker`, not editable; affinity icons use the icons' palette line 1, `itemIconUrl(id, 1)`).
- `units.py`: unit groups, REDA paths, chapter event groups. A named ally's level comes from their sheet, shown read-only in the chapter (`DecompData._with_sheet_levels`, `shownLevel`): for units the project adds, or everywhere once the sheet differs from the game; autolevelled units keep theirs. Enemies and generics are set in the chapter; the "Automatic levels" box of the unit panel writes `autolevel`, on the game's units too.
- `objectives.py`: goal settings + victory events; DecompData.read_objective / apply_objective.
- `maps.py`: map rendering, tileset sheet, layout encoding, terrain names; map changes, movement costs, terrain effects (`terrain_effects`: avoid / def / res bonuses, foot and horse costs, shown in the map editor); painted layouts and edited change sets in project `data/maps.json`, applied by `DecompData.apply_maps`; another tile sheet of the game per layout in "bases" (`base_choices`, `with_base`, `layout_assets`, `convert_by_terrain`): pass the base to everything that reads a layout's assets, and tile edits work on `tileedit.layout_for(base)`.
- `showOriginal` in `fe-maker.json` (off for a blank project; `GameOptions`): elements with the class `to-original` go away under `.hide-original` (`app.css`); every new action going back to the original game gets that class.
- Palette colors: `paletteColors` in `data/maps.json` (palette symbol -> index -> #rrggbb), written over the `.pal` by `maps.edited_palette` for every chapter on that palette, each fog twin keeping how much lighter it was; previews through `maps.with_colors`. The map editor picks a colour by a click on the map from a coded sheet (`render_tileset(coded=True)`: red = line * 16 + index) and recolours it with its shades like a character (`PaletteFamilies.svelte` + `lib/colors.ts`, shared with `CharacterColors.svelte`; ticket 147).
- Map change sets: a layout without one gets it at build time, only once it has a change (`maps.add_change_set`, a new entry at the end of `gChapterDataAssetTable` by `maps.add_asset`, `changeLayerId` of its chapters); the API shows such a layout with an empty list. `MapEditor.resize` moves the four sides; left and top move changes, object settings, units and objectives too (`chapters.json`, its own undo step), and `offsets` in `data/maps.json` makes the original location events follow at build time and keeps moved objects from counting as new.
- `mapobjects.py`: villages, houses, chests, doors, cracked walls, snags found by terrain; their used state learned from the original changes per tileset; new objects get a map change and a location event at build time, `DecompData.apply_maps` / `_apply_map_events`; object settings in `data/maps.json` "objects".
- `tileedit.py`: mirrored and turned metatiles added to a tileset's free slots, new 8x8 tiles for quarter turns; project `data/maps.json` "tilesets" by tile config name; rewrites the TileConfig `.bin` and the 4-bit grayscale `ObjectType` PNG, written by hand since Pillow cannot.
- `quotes.py`: battle quotes and death quotes tables, new quotes added before the end of the lists.
- `dialogues.py`: messages as steps: face, clear, move, say, code; parse/render round-trips all 3404 game messages; chapter scenes and their triggers (`with_trigger`, `without_scene` for `removedScenes`); project `data/dialogues.json` by message id, applied by `DecompData.apply_dialogues`; `layout` cuts lines too wide for the box at build time, mirrored in `ui/src/lib/textLayout.ts` for the preview.
- `fonts.py`: glyph widths and glyph sheet of the game's fonts; cp1252 characters, accented letters written as `[é]` codes defined in an overlay `textdefs.txt` by `TextFile.render` / `changed_files`.
- `events.py`: event scripts as commands for the visual editor `ScriptEditor.svelte` (`GiveItem` is the editor's own, written as SVAL + GIVEITEMTO); memories, the player's past choices: named permanent flags 240-300 (`MEMORY_FLAGS`, `data/dialogues.json` "memories"), a question is a scene message with `question` (`dialogues.as_question`); edited scripts in `data/dialogues.json` "scripts", `DecompData._apply_scripts`; event files load with `_load_event_sources`, without the chapter settings.
- `unitstats.py`: the event command `ChangeStat` (the editor's: three slots and `ASMC(FemChangeStat)`), the function added to `src/bmunit.c` only when a script uses it; works on the unit as it stands, nothing if the character has no unit yet.
- `averagestats.py`: stats of a unit entering a chapter, as `LoadUnit` computes them, with the average of automatic levels (`POST /api/units/stats`, which also returns the weapon ranks, `validation.unit_ranks`).
- New turn, area and flag scenes (dialogues `quotes`) may carry `commands`: `DecompData._scene_script` writes them instead of the message alone, `new:<key>` being the scene's own message; `ScriptEditor` edits them with its `quote` prop.
- Scene groups: `chapters.newGroups[name].scene` marks a group only scenes bring; `DecompData._add_reinforcements` writes it without a turn event and `_declare_new_groups` adds its `extern` in the event file of each script that loads it; `GET /api/chapters/{i}/units` gives `loadedBy` (scripts per new group).
- Build progress: `build-lines.txt` in the config dir keeps the last finished build's line count; `GET /api/project/build` gives it as `expected`, the build panel's percentage.
- `battlebg.py`: preview of a battle background set (its plains background): whole 240 x 160 PNGs, or tile sheet + 30 x 20 tilemap (`.bin`), with the 160-color palette.
- `itemicons.py`: item icons imported on the 11 ids the game leaves unused, in the shared icon palette (`data/icons.json`, `assets/icons/<id>.png`).
- `supports.py`: support pairs and their C/B/A conversations; edited list in `data/dialogues.json` "supports", new pairs' conversations are quotes of kind "support"; `DecompData._apply_supports`.
- `portraits.py`: 128 x 112 portrait sheets <-> the decomp's four portrait files, mouth/eye detection; imported sheets in the project's `assets/portraits/`, data `data/portraits.json`, `DecompData.apply_portraits`; portrait ids start at 1; an id past the game's table (`first_new_id`, 173) is a new portrait `portrait_New<id>_*`, added to `data_portrait.s`, `portrait_pointer.h`, the table and `textdefs.txt` as `[FID_New<id>]`.
- `weaponrange.py`: ranges the game does not list (1-10...): `GetItemReachBits` (one bit per distance from bit 8), the range text and the two red-square functions rewritten only when a weapon has such a range.
- `reach.py`: move, strike and staff (`heal`) cells of units on a chapter's map, without other units in the way: `POST /api/chapters/{index}/reach`, overlay in `ChapterEditor`.
- `danceanim.py`: a class or character that dances without a dancer's sprite: the map animation is skipped (it reads past the sprite's list otherwise, a crash of the original game too); written only then.
- `chapterflags.py`: temporary flags above 40 cleared at each chapter, and up to 56 kept by a suspend: `ResetChapterFlags` and the saved size rewritten only when a project uses them.
- `prep.py`: preparations screen per chapter (`data/chapters.json` "prep", on by default in added chapters), the opening scene's `CALL(EventScr_08591FD8)`, `DecompData.apply_prep`.
- `strmag.py`: Strength/Magic split (game option `strMagSplit`): Magic in the unit's byte `_u3A`, tables by class and character in `bmunit.c`, `BATTLE_ATTACK_STAT_FEM` in combat, Magic bytes of each save slot in the bonus-map zone of the save memory; ticket 164's temporary bonuses move to an IWRAM table (`sym_iwram.txt`). In the UI, `ui/src/lib/magic.svelte.ts` (option state, Magic defaults mirroring `class_magic` / `character_magic`, `withMagic` columns, `statLabel`) is used by the character, class, item, chapter and event editors; `averagestats.average_stats` adds `mag` when given the classes.
- `battlenumbers.py`: game option `battleNumbers` (ticket 169), C-SkillSys's AnimNumber: `NewEfxAnimNumberFem` and its anim script in `banim-efxhpbar.c`, called from `NewEfxFlashHPBar` (damage, the hit's `hpChange`), efxHPBarLive (heal) and efxHPBarResire (drain); tiles of the game's MISS / NO DAMAGE text (OBJ 0x6012000), OBJ palette 15; image downloaded into `config_dir()/cskillsys`, saved as a 4-bit PNG, included in `data/banim-efxhitfx.s`.
- `skills.py`: skills (game option `skills`, ported from C-SkillSys at a pinned commit; plan `docs/competences.md`): `CATALOGUE` (passive skills: stat, battle, order) and `GAME_SKILLS` (the game's class abilities shown as skills); `used()` numbers the project's skills 1..N (`SKILL_FEM_<id>`, `SKILL_COUNT_FEM` in their own header `include/skills_fem.h`, included by the C files using them and by `eventscript.h`, ticket 34); `apply()` (after `strmag.apply`) writes `gCharacterSkillsFem` / `gClassSkillsFem` and `SkillTesterFem` in `bmunit.c`, wraps the stat getters a skill raises (never under 0; `show_malus`, shared with the items' temporary bonuses, draws a malus "-N" in red on the status screen (palette 10), ticket 50), splits `ComputeBattleUnitStats` (the actor's call computes both units' base stats in `ComputeBattleUnitBaseStatsFem`, then each call applies its unit's `ApplyBattleSkillsFem` and clamps at 0, as C-SkillSys's PreBattleCalc; skipped in the arena and on the stat screen), runs the comparisons with the foe (`late` skills, `ApplyLateBattleSkillsFem`) at the start of `ComputeBattleUnitEffectiveStats` and the hit and crit ones (`eff`, a `holder` that may be the defender) at its end, stat skills on several stats under a condition (`stats`, `when`), rewrites `BattleUnwind` for Vantage / Desperation, hooks the triggered skills into `BattleGenerateHitAttributes` / `BattleGenerateHitEffects` (`SkillProcFem`, Sol/Aether flag at `DRAIN_FLAG` in free RAM), and Adept / Astra into `GetBattleUnitHitCount` (rounds cut at the game's 6 hits, Astra flag at `ASTRA_FLAG`), and the triggered skill's name in battle animations (`SHOWN_SKILLS`: the skill noted with its hit; `StartSkillNameFem` in `bmbattle.c`, called at C07 from `banim-main.c`; the status a skill inflicts noted per hit at `STATUS_HITS`, flashed on its unit by `StatusHitFem`, called when a hit lands from `banim-ekrutils.c`, ticket 33; Huichelaar's box downloaded by `box_png`; in map battles `StartSkillIconMapFem`, called from `MapAnim_PrepareNextBattleRound`), keeps the learned skills (`_learned`: `LearnSkillFem` / `ForgetSkillFem`, table at `LEARNED_TABLE`, saved per slot at `LEARNED_SAVE` in the bonus-map zone like Magic; `LearnLevelSkillsFem` after level-ups and promotions from the sheets' `learnedSkills`; `FemSkillEvent` ASMC for the events' GiveSkill / RemoveSkill, whose skills `event_skills()` adds to `used()`; `LearnedPopupsFem` popups after battles; batch 4: the game abilities in `ASSIGNABLE`, when a sheet or event gives one, are added to `UNIT_CATTRIBUTES` by `SkillAttributesFem`; `_map_skills`: Canto+, Renewal, Galeforce in `playerphase.c` / `bmtarget.c`; `_menu_skills`: unit-menu commands in `menu_def.c` / `bmmenu.c`, their names added by `add_texts` as `menu:<id>`), appends the icons after the game's 224 (lookup table moved to free RAM at `ICON_TABLE`) and draws "Skills" with the icons and R help on status page 1; `add_texts()` runs before `changed_files()`. Icons are downloaded once into `config_dir()/cskillsys` (`/api/skills/{id}/icon.png`); `/api/skills` gives the catalogue. UI: `ui/src/lib/skills.svelte.ts` (option state, catalogue, game skills from abilities) and `SkillsPanel.svelte` on the character and class sheets, skills chosen in `SkillPicker.svelte` (search, categories from each skill's `group`). `tools/cskillsys_watch.py` lists upstream changes since the pinned commit. After the action (`_post_action_skills`): a proc started from the player phase and `gProcScr_CpPerform` before `HandlePostActionTraps` shows each HP change after a battle with the game's damage or heal animation on the map, then applies it (C-SkillSys's PostActionHook). The seals, first in that proc, play C-SkillSys's animation (its two images downloaded by `seal_anim_png`, incbinned in `data_item_icon.s`) and reuse the items' temporary bonus counters: `project.build` sets `DecompData.temp_bonuses_wanted` (`skills.uses_temp_bonuses`) before `changed_files()`.
- `seize.py`: who can seize: `CanUnitSeize` rewritten only when characters' `canSeize` change.
- `convoy.py`: who opens the convoy and the chapters without it; `SupplyUsability` / `HasConvoyAccess` rewritten only when the project changes them; characters' `convoyAccess`, chapters' "convoy".
- `story.py`: how chapters follow each other: MNCH / MNC2 / MNC3 / MNC4 / MoveToChapter commands, `DecompData.chapter_links`; edits are edited scripts in `data/dialogues.json` "scripts", shown in the "Story flow" tab `ChapterFlow.svelte`.
- `banim.py`: battle animations read from the decomp's text scripts and PNG sheets, drawn as strips of frames for the Classes tab player: `/api/classes/{id}/animations`, `/api/animations/{n}/{mode}.png|json`.
- Empty movements: `banim.empty_modes` (at most one picture, or a ranged attack without spell), crossed with the weapons a class can wield (`validation.weapon_users`), shown by `BattleAnimation.svelte`: orange, red if a weapon needs it.
- `ferepo_ranged.json` (made by `tools/scan_ranged_animations.py`): FE-Repo animations whose sword, lance or axe casts a spell in FEditor's mode 5, names only; the library's `ranged` filter reads it, so it needs no GitHub API call.
- `banim_import.sound_files`: FEditor's `S` command is stored as `banim_code_85 0x<song>48`; only when an imported script uses it, the overlay patches `src/animedrv.c` and `src/banim-efxsound.c` to play it (an unmodified project stays byte-exact).
- `banim_import.py`: FEditor / FEBuilder animation scripts (from FE-Repo or the user's PC: a weapon's folder or .zip, `/api/animations/import/local`) and 248 x 160 frames converted to the decomp's files: frames cut into GBA sprites, packed in 256 x 64 sheets, origin (0x94, 0x58); `export_feditor` does the reverse; imported animations kept in the project's `assets/animations/<key>/`, `data/animations.json`, added after the game's at build time by `DecompData.apply_animations`: table, pointers, sheet externs, compressing linker list, one new `AnimConf_FEM_<class>` array per changed class.
- `charpalettes.py`: a character's own battle colours by class (FEBuilder's Unit Palette): characters' `battleColors`, 5 lines of 16 colours or null for the class's; `gAnimCharaPalConfig` / `gAnimCharaPalIt` rewritten, new palettes after the game's 108 rows, `DecompData.apply_character_palettes` before `apply_animations`; `customColors`: the user's own colours by class while another choice is in use, never built; `CharacterColors.svelte` (`BattleAnimation` in `preview` mode, cropped to what the frames draw, with a zoom, reads each pixel's colour number from a strip drawn in coded colours and repaints in the browser), `/api/characters/{id}/battle-colors/{class}`.
- `portraitcolors.py`: a character's colours for a class drawn from a portrait (`GET /api/classes/{id}/portrait-colors`, button in `CharacterColors.svelte`, a proposal kept or dropped, colours and families swapped by dragging): the game's palettes of the animation say which slots are the character's, hair first (slots 6-7, sometimes 5, unless hidden under a helmet; on the portrait, the largest group of hues around the head); wyverns: body and wings' membrane tinted apart (`WYVERN_BODY`, `WYVERN_WINGS`).
- `mapsprites.py`: map sprites imported for a class (FE-Repo pairs `-stand.png` / `-walk.png`, or the PC), converted to the player palette's indices; project `data/mapsprites.json` + `assets/mapsprites/<key>/`; `DecompData.apply_map_sprites`: new sheets, rows after the game's in `unit_icon_wait_table` (128 at most, read with `id & 0x7F`), the class's `unit_icon_move_table` row points to the new walking sheet with its own motion (`_with_moving_sprites`, shared with the added classes).
- `pieces.py`: whole buildings of the original maps, found by terrain, offered as blocks, and one-tile pieces by terrain (group `building` or `decor`, also tiles of the sheet no map draws): `/api/maps/{id}/pieces`.
- `autotile.py`: terrain brushes whose tiles join by themselves, learned per tile sheet from the game's maps and from the tiles' pixels (which materials each border shows), solved by wave function collapse so that every two tiles side by side can touch: `/api/maps/{id}/brushes`, `/autotile`; the "Terrains" panel of `MapEditor`, applied at the end of a stroke. `fill` (`/fill`, "Fill the empty space"): patches of walkable ground in the map's most common terrain, joined one by one, everything else kept.
- `tiled.py`: .tmx export / import in the community's tmx2ea layout; files in the project's `tiled/` folder.
- `assets.py`: portraits, item icons, map sprites; `face_preview` = big dialogue portrait; `card_names`, `card_preview`: class cards, portrait rows without a face, what classes' `genericPortrait` (`defaultPortraitId`) points to.
- `tweaks.py`: test start modes.
- `gameoptions.py`: options of the built game ("Game options" tab, fe-maker.json `gameOptions`): defaults of a new save in `InitPlayConfig`, comfort switches rewritten from FEBuilder SYSTEM patches; only what the project changes is written. The Staff & Dance line is the second of the game's Configuration menu, whose rows move up one tile row to fit a 14th.
- `server/fe_maker/decomp/music.py`: MIDI imported for a chapter's player phase: a free row of `gSongTable` (dummy_song), its `songs.mk` rule (mid2agb, the game's instruments), its `linker_script_sound.txt` line; files `song<n>_fem_<key>` (`docker/entrypoint.sh` removes leftovers: a .mid without rule stops the build); project `data/music.json` + `assets/music/`.
- `server/fe_maker/decomp/chaptitle.py`: title strips (256 x 16 pictures, `chap_title_data`) of the chapters the project adds, drawn with the game's own letters, read at build time from the strips of the user's decomp (never stored), the talk font for the letters no title has; rows from 0x58, `chapTitleId` in the chapter settings, `DecompData._add_title_images`.

## UI

- `ui/` (Svelte 5 runes + TypeScript, Vite): one editor component per tab. The dialogue editor has a "conversation" view (`ConversationThread.svelte` + `FacePicker.svelte`) and the steps view; `MapEditor.svelte` paints on a canvas from the tileset sheet `/api/maps/{id}/tileset.png`; `EditableList` (undo + autosave), `RecordList` (list with icon/suffix snippets).
- Workflow (30/10/2026): a project opens on Campaign; top tabs follow the work (`Workspace.TABS`), the Chapters tab has three views (`CHAPTER_VIEWS`: chapters, maps, dialogues) on one `currentChapter`.

## Build, test and release

- `server/fe_maker/playtest.py` + `docker/playtest/` (image `fe-maker-playtest`: mGBA 0.10.5 static lib + `driver.c`, a stdin/stdout line protocol): play a built ROM without any window, about 100 times faster than real time. `Game(rom, map_path)` holds keys for N frames, reads/writes memory by decomp symbol (`BuildOutput.map_path`, the build's `fireemblem8.map`), takes screenshots; `chapter()`, `turn()`, `phase()`, `units()`. In-game checks, on its test bench (`_bench` in `tests/local/test_playtest.py`): it works while the user is on the PC.
- Release (alpha): `tools/make_release.py` zips the server, `ui/dist`, the image's sources and the launchers, never the decomp or a ROM; `decompfetch.py` downloads the decomp at `paths.DECOMP_COMMIT` into the config dir (`paths.DECOMP_DIR`: `FE_MAKER_DECOMP`, the submodule, else that copy); `checks.py` + `Checks.svelte`: what the computer lacks (`start_docker` starts Docker Desktop at launch, ticket 146); `builder.ensure_image`: image tagged by the hash of its sources, local, else ghcr.io (`.github/workflows/image.yml`), else built.
- Build times (ticket 30): `builder.BuildResult.seconds` (inside the build lock, not the wait) and `native`; `project._timing` counts the C files compiled (agbcc lines of the log); `buildtimes.py` keeps the last 200 in `<config>/build-times.json`, `/api/build-times`; `BuildPanel.svelte` shows the duration, the previous build of the same kind and the history.
- Build cancel (ticket 40): `buildcancel.py` holds the running build's process (make, or `docker run` with its named container); `POST /api/project/build/cancel` kills it with its children, the build raises `BuildCancelled` (state `cancelled`), and the files written since make started (objects, the C files' assembly, the ROM) are removed so that the next build makes them again.
- `native/asmdeps.py` (ticket 30): scaninc's scan in Python for all assembly sources at once, written to `.fem-asmdeps.mk` in the working copy and included by `win.mk`; make runs with `NODEP=1`, and `win.mk` cancels make's built-in rules but `%.o: %.s` (battle animations' motion files); a build with no change went from ~25 s of make to ~2 s.
- `server/fe_maker/native/`: native Windows build, no Docker (docs/sans-docker.md). `builder.build` uses it when the toolchain is installed (`toolchain_dir()`, `FE_MAKER_TOOLCHAIN`; `FE_MAKER_BUILDER=docker` forces Docker): working copy in `<config>/work/decomp[-bugfix]`, synced in Python like rsync --checksum (`sync`, files of the previous overlay recorded in `.fe-maker-overlay` and restored), then the decomp's Makefile run by the toolchain's make and busybox with `win.mk` (objects.lst written by make, `jsonproc.py` for the unlicensed jsonproc, scripts through `$(PYTHON)`, `banim_link.py`: the compressing linker's output in seconds), preprocessor `arm-none-eabi-cpp`. Toolchain archive: `tools/build_toolchain.py`, published by `.github/workflows/toolchain.yml` as release `toolchain-<TOOLCHAIN_VERSION>`, downloaded by `/api/toolchain/download`; the first build runs in the background from `checks.py` (`start_warmup`, check `firstBuild`).
- `docker/`: build image (Ubuntu 24.04, agbcc pinned). The decomp is mounted read-only, the working copy lives in a Docker volume, the overlay is applied with `rsync -rlp --checksum`.
- "Test this chapter": test option `chapter` (fe-maker.json testOptions), `tweaks.start_on_map(source, chapter)` sets `gPlaySt.chapterIndex` after `WriteNewGameSave` in the quick start, then loads the chapter's player units (`LoadUnits(GetChapterAllyUnitDataPointer())`, ticket 45: chapter 1 loads none, it moves the army of the chapters before; event loads reuse units already there).

# FE Maker — notes for Claude

FE Maker is an easy (« RPG Maker »-like) editor for Fire Emblem: The Sacred Stones (FE8 US), built on the fireemblem8u decomp (`decomp/`, git submodule). The specification `CAHIER_DES_CHARGES.md` is the reference; work goes phase by phase (section 4).

## Keep the docs up to date

Every commit that changes what FE Maker can do updates the docs in the same commit:

- `CAHIER_DES_CHARGES.md`, section 4: progress of the current phase (what is done, the date, what is left, what is not tested in game yet).
- `README.md`: the status banner (FR and EN) when a feature area is added.
- `docs/audit-decomp.md`: anything learned about the decomp (data formats, limits, original-game bugs).
- `CREDITS.md`: any code, data or idea taken from another project (FEBuilderGBA, FE-Repo...).
- This file: any new rule, pitfall or architecture fact worth knowing in a later session.
- `CLAUDE.local.md` (personal, not committed, if present): the current status and next steps.

Docs are written in French (README in French and English); code and comments in English; UI in FR, EN, ES and IT (`ui/src/locales/*.json`, flags in `LangFlag.svelte`): every new UI string goes into all four files (`tests/server/test_locales.py` checks they have the same keys).

## Rules

- Never commit ROMs, `.gba` files or assets extracted from the game. The decomp stays an unmodified submodule; modified decomp files exist only in the build overlay (the decomp has no license, so modified decomp code is never redistributed).
- Do not add fixes tied to the original FE8 story unless the user asks: tell the user instead. The goal is to let users rebuild everything from scratch; the original story is only test material.
- Everything mentioned in the UI is clickable and opens its sheet (spec principle 8): use `Mention` and the navigator (`ui/src/lib/navigation.svelte.ts`).
- Class gender is shown after the class name: ♂ blue, ♀ pink (`GenderSign`).
- FEBuilderGBA (GPL-3.0) may be used freely as a reference or source; credit it in `CREDITS.md`.
- Don't write things from scratch when an existing resource saves time and tokens: before coding a feature (engine behavior, ASM hack, event command, map/tile tool, data format reader, editor logic...), look at what already exists and reuse or adapt it when it fits. First FEBuilderGBA as a whole (its patches in `config/patch2/FE8U/`, its source code, its data/config files), then any other resource: FE-Repo / FEU (Fire Emblem Universe) hacks and tools, Event Assembler and its libraries, the decomp itself, Python/JS libraries. Check the license allows reuse and credit it in `CREDITS.md`.
- Where to look: FEU's "Getting Started" index of tutorials and FEBuilder docs (https://feuniverse.us/t/getting-started/10320); laqieer's FEBuilderGBA fork (https://github.com/laqieer/FEBuilderGBA, GPL-3.0, archived 20/10/2026: cross-platform core, CLI, decomp support preview, headless mGBA playtests).
- An unmodified project must rebuild the original ROM byte for byte: only write what changed (`changed_files()`, cparse re-renders only edited entries).
- Patches are `.ups`. BUGFIX build option exists but is off by default (3 decomp BUGFIX blocks don't compile).

## Architecture

- `server/fe_maker/` (Python, FastAPI): `api.py` endpoints, `project.py` (project folder: `fe-maker.json` + `data/*.json`, migrations, build), `builder.py` (Docker build), `validation.py` (problems shown in the UI), `emulator.py` (mGBA launch and controls), `ups.py`.
- `server/fe_maker/ferepo.py`: FE-Repo browser (index `file_urls.json` and downloaded files cached in the user's config dir `ferepo/`; licence and authors read from file names; `Project.update_credits` writes them to the project's CREDITS.txt). Tests mock `_download`: never download from tests.
- `server/fe_maker/decomp/`: reading and writing the decomp. `gamedata.py` (characters, items, classes, combat, chapters; apply order classes → characters → items → combat → chapters), `cparse.py` (designated-initializer parser), `combat.py`, `units.py` (unit groups, REDA paths, chapter event groups), `objectives.py` (goal settings + victory events; DecompData.read_objective / apply_objective), `maps.py` (map rendering, tileset sheet, layout encoding, terrain names; map changes, movement costs; painted layouts and edited change sets in project `data/maps.json`, applied by `DecompData.apply_maps`; another tile sheet of the game per layout in "bases" (`base_choices`, `with_base`, `layout_assets`, `convert_by_terrain`): pass the base to everything that reads a layout's assets, and tile edits work on `tileedit.layout_for(base)`), `mapobjects.py` (villages, houses, chests, doors, cracked walls, snags found by terrain; their used state learned from the original changes per tileset; new objects get a map change and a location event at build time, `DecompData.apply_maps` / `_apply_map_events`; object settings in `data/maps.json` "objects"), `tileedit.py` (mirrored and turned metatiles added to a tileset's free slots, new 8x8 tiles for quarter turns; project `data/maps.json` "tilesets" by tile config name; rewrites the TileConfig `.bin` and the 4-bit grayscale `ObjectType` PNG, written by hand since Pillow cannot), `quotes.py` (battle quotes and death quotes tables, new quotes added before the end of the lists), `dialogues.py` (messages as steps: face, clear, move, say, code; parse/render round-trips all 3404 game messages; chapter scenes and their triggers; project `data/dialogues.json` by message id, applied by `DecompData.apply_dialogues`; `layout` cuts lines too wide for the box at build time, mirrored in `ui/src/lib/textLayout.ts` for the preview), `fonts.py` (glyph widths and glyph sheet of the game's fonts; cp1252 characters, accented letters written as `[é]` codes defined in an overlay `textdefs.txt` by `TextFile.render` / `changed_files`), `events.py` (event scripts as commands for the visual editor `ScriptEditor.svelte`; edited scripts in `data/dialogues.json` "scripts", `DecompData._apply_scripts`; event files load with `_load_event_sources`, without the chapter settings), `supports.py` (support pairs and their C/B/A conversations; edited list in `data/dialogues.json` "supports", new pairs' conversations are quotes of kind "support"; `DecompData._apply_supports`), `portraits.py` (128 x 112 portrait sheets <-> the decomp's four portrait files, mouth/eye detection; imported sheets in the project's `assets/portraits/`, data `data/portraits.json`, `DecompData.apply_portraits`; portrait ids start at 1; an id past the game's table (`first_new_id`, 173) is a new portrait `portrait_New<id>_*`, added to `data_portrait.s`, `portrait_pointer.h`, the table and `textdefs.txt` as `[FID_New<id>]`), `seize.py` (who can seize: `CanUnitSeize` rewritten only when characters' `canSeize` change), `convoy.py` (who opens the convoy and the chapters without it; `SupplyUsability` / `HasConvoyAccess` rewritten only when the project changes them; characters' `convoyAccess`, chapters' "convoy"), `story.py` (how chapters follow each other: MNCH / MNC2 / MNC3 / MNC4 / MoveToChapter commands, `DecompData.chapter_links`; edits are edited scripts in `data/dialogues.json` "scripts", shown in the "Story flow" tab `ChapterFlow.svelte`), `tiled.py` (.tmx export / import in the community's tmx2ea layout; files in the project's `tiled/` folder), `assets.py` (portraits, item icons, map sprites; `face_preview` = big dialogue portrait), `tweaks.py` (test start modes).
- `changed_files()` values are text, or bytes for binary files (`.mar` map layouts); the overlay writer handles both.
- UI theme (25/10/2026, from the clickable mockups https://claude.ai/artifact/MKewiQUGuDhGbfbYt1UGsL): colors, radii and the header colors are CSS variables in `ui/src/app.css` (`--header*`, `--radius-big`, light and dark); the font is Nunito, bundled with `@fontsource-variable/nunito` (no network). Use the variables, not new hard-coded colors; `button.play` is the green "Test" button. The screens' layouts follow the mockups one by one, when each screen is redone.
- `ui/` (Svelte 5 runes + TypeScript, Vite): one editor component per tab (the dialogue editor has a "conversation" view, `ConversationThread.svelte` + `FacePicker.svelte`, and the steps view) (`MapEditor.svelte` paints on a canvas from the tileset sheet `/api/maps/{id}/tileset.png`), `EditableList` (undo + autosave), `RecordList` (list with icon/suffix snippets).
- `docker/`: build image (Ubuntu 24.04, agbcc pinned). The decomp is mounted read-only, the working copy lives in a Docker volume, the overlay is applied with `rsync -rlp --checksum`.
- Before every commit, run what CI runs: `server/.venv/Scripts/python -m ruff check server tests docker` (lines up to 130 characters), `pytest tests/server`, and `npm run check` in `ui/`. CI failed silently for a dozen commits on 23/10/2026 because ruff was not run locally.
- Testing beside the user's running app: start a second server with `FE_MAKER_HOME=<scratch home>` (own settings, a copy of the `rom/` folder, own projects), `FE_MAKER_UI_DIST=<scratch build>` (`npx vite build --outDir <dir>`) and `--port 8766`. The user's server, project and `ui/dist` stay untouched.
- Tests: `tests/server` (no ROM, fictional fixtures in `tests/server/fixtures/decomp`); `tests/local` (needs the ROM and Docker, never in public CI).
- `server/fe_maker/playtest.py` + `docker/playtest/` (image `fe-maker-playtest`: mGBA 0.10.5 static lib + `driver.c`, a stdin/stdout line protocol): play a built ROM without any window, about 100 times faster than real time. `Game(rom, map_path)` holds keys for N frames, reads/writes memory by decomp symbol (`BuildOutput.map_path`, the build's `fireemblem8.map`), takes screenshots; `chapter()`, `turn()`, `phase()`, `units()`. Use it for in-game checks: it works while the user is on the PC. Example: `tests/local/test_playtest.py`.
- `server/fe_maker/__main__.py`: a launch while FE Maker runs restarts it (`POST /api/shutdown`, refused with 409 during a build; an older server without it is killed by the PID listening on the port, Windows only). My own server on 8765 is replaced too when the user clicks the shortcut.
- `tools/mgba-drive.ps1` (Windows, dev only): drives the mGBA window with key presses. Only when the user is not using the PC: if mGBA loses focus, the keys go to other windows. Prefer `playtest.py`.
- Feedback tickets: `server/fe_maker/tickets.py` (stored in the user's config dir, `tickets/tickets.json` + `images/`, never in the repo), `TicketPanel.svelte` (side column opened by the header button), `ui/src/lib/appContext.svelte.ts` (tab / record / detail attached to a ticket; `RecordList` and `ChapterEditor` fill it). List open tickets with `python -m fe_maker.tickets`.

## Pitfalls already met

- The decomp checkout must use LF line endings (`core.autocrlf=false`, `core.eol=lf`), or the Linux build breaks.
- Text compression packs 2 bytes per symbol: odd-length names need `[.]` padding (`name_message`).
- Unit definitions set each unit's class in every chapter: a character class change must retarget unit defs. The character sheet is the only source of a named character's class: chapter edits never write `classIndex` for `CHARACTER_` units (class 0 = the character's class when a unit switches to a named character); only generic units (raw ids 0x80...) get a class per chapter.
- Weapon ranks a class cannot animate crash the battle animation (validation `noBattleAnimation`).
- Weapon locks: generic CA/IA_LOCK 1,2,4,5,6,7 are allocated automatically from items' `reservedFor`; LOCK_3 means monster weapon.
- Map tileset PNGs are inverted grayscale (index = 15 − v/17); map palettes: 5 normal then 5 fog palettes.
- Several chapters share an internal id: key chapters by index.
- Map layouts are keyed by layout id (file stem): several chapters can share one, so painting it changes all of them (the UI says so). Map change sets are keyed by layout id too (one per layout).
- Map checks against units (`_validate_chapter_maps`) only report what the project changed: the original game has units outside their map and under roofs removed by map changes.
- Bash heredocs passed through the tool break on some quote/backslash mixes ("unexpected EOF"): write the patch script to the scratchpad and run it.
- Editors loaded asynchronously (chapters, maps) must read `nav.focus` once their list is loaded: `followFocus` alone misses a link that mounted the tab.
- An item reservation equal to the original one is never rewritten (the original Mani Katti is reserved for nobody; an edited empty reservation means unrestricted).
- PowerShell eats backticks in inline scripts: edit files with the Edit tool or Python, not PowerShell strings.
- Docker fails to start when CPU virtualization is off in the BIOS (happened several times on the user's PC).
- Opening scenes often load units on other maps (cutscenes): `chapter_unit_groups` marks groups loaded before the last `LOMA` as "cutscene"; editing them does not change the battle.
- Bash heredocs passed through the tool can mangle `\b` in Python sources: edit regex code with the Edit tool.
  The same goes for `\n` and `\x00` in a heredoc'd patch script (they became real newlines and NUL bytes): write such scripts with the Write tool.
- C code FE Maker writes into the decomp: no `static const` tables in a function of a file whose `.rodata` the link script discards (`bmcontainer.o`, others): the link fails with "defined in discarded section `.rodata`". Write comparisons; compile with `tests/local` before telling the user it works.
- The game takes the first matching entry of its quote tables (`GetBattleQuoteEntry`, `GetDefeatTalkEntry`): a new entry must go before the game's entries it would lose to (`quotes._battle_position`). Supports: the "Support" command appears only when the points sit exactly at 80 / 160 / 240; a pair starting at 81+ skips its C conversation (`supports.skipped_levels`).
- Test builds' simplified prologue skips the scene that gives Eirika the Rapier: she has no weapon unless the project gives her one (story-tied, left as is; told the user 24/10/2026).
- In playtests, wait for animations before reading the screen (`press` waits 20 frames; a move takes ~40), pick menu entries by their position (menus differ with the situation: Attack only when an enemy is in range), and remember Canto (Seth can move again after an action).
- Show validation problems with `problemText(p)` (`ui/src/lib/i18n.svelte.ts`), not `t('problem.' + code)`: it turns `terrain`, `object` and `wtype` parameters into names.
- `validation.weapon_problem` mirrors `CanUnitUseWeapon`; unusable weapons are reported only when the project changed something (`_validate_unit_weapons`), on the edited unit or once on the changed sheet.
- `assets.portrait_names` (and other readers) are `lru_cache`d: copy the list before adding to it (`list(...)`), or every later call sees the additions.
- Svelte `$derived` lists already hold a record right after `list.update` adds it: take its index before saving ("Add a change" opened nothing because of this).
- Text byte counts (padding to even runs) use `texts.text_size`: an accented letter is one byte in the game, not its UTF-8 length.
- Changing where a chapter leads works in game (playtest); the prologue sent straight to chapter 2 showed its title, then stayed black (24/10/2026): the game took chapter 2 for a skirmish (ticket 39, see the world map pitfall below and docs/audit-decomp.md item 57); fixed when the project goes without the world map.
- Map tile edits proposed by a mirror/turn are not saved until the user creates them (`pendingTiles` in `MapEditor.svelte`); removing an added metatile also drops the 8x8 tiles only it used (`ui/src/lib/tileEdits.ts`).
- Map objects: only objects that are new on the painted map get automatic changes and events; original objects keep their original behavior (some are decoration without event) unless the project sets them. A change only counts for an object if it puts it in its used state (`USED_TERRAIN`): a village painted inside a brigand-ruin rectangle would else ruin the wrong village.
- The user's server may be older than `ui/dist` (it serves the rebuilt UI until they restart it): UI code reading a new API field must fall back to the old answer. Ticket 22's "used tiles" check read `originalTileset`, which the old server did not send, so every added tile looked unused and a used one got removed. Map cells on a removed added tile are now a validation warning (`missingTile`).
- A village is destroyed through the change holding its roof (one cell above the gate), and the engine keeps the last change holding a cell: new villages get a ruined-village change written before all the other changes (`mapobjects.ruin_change`, `obj["ruin"]`), so the gate's last change stays the closed village. Playtests that end the turn must open the map menu on an empty cell (`game.units()` positions), and an enemy boss dying on a counter ends the prologue before other enemies act.
- C-SkillSys prototype (`docker/cskillsys/`, ticket 27, stopped 24/10/2026): its build takes 10+ minutes (run it in the background); builds now also output `fireemblem8.elf`. It rebuilds every game text from its own copy and replaces item/spell tables, so it would erase FE Maker's edits: see `docs/separation-force-magie.md` before going further.
- Event scripts can use messages made by the project: quotes of kind "scene" with a "key", referenced as "new:<key>" (`dialogues.SCENE_MESSAGE`); `apply_dialogues` adds them and rewrites the arguments. A rewritten opening scene must bring the army back with `LOAD2` on the chapter's players group (`ScriptEditor.simpleScene`).
- Playtest harness: a chapter's turn/phase say "player" while its opening scene still runs; tapping A after it selects units. Wait for the scene to end before acting (see the scratch dry run notes in CLAUDE.local.md).
- MNCH / MoveToChapter go to the chapter of the lord's world map node, not to their argument: test builds started on the map, and projects with the "world map" option off (`Project.world_map`, `fe-maker.json` "worldMap", exported patch too, ticket 39), redefine MNCH as MNC2 (`tweaks.without_world_map`). The original story's MNCH arguments are often stopover chapters (chapter 1 -> Castle Frelia, 56). Without the world map, `GetBattleMapKind` must return STORY too: it takes any chapter from 2 on whose world map place was never reached for a skirmish and runs the skirmish opening (black screen, ticket 39). To debug a stuck playtest, list the live procs and the event engine's current command (sProcArray at the start of proc.o's EWRAM, 0x6C per proc). The "Story flow" tab is now the "Campaign" page (`ChapterFlow.svelte`, tab id still `flow`). A character's new portrait follows them in dialogues (`DecompData._follow_portraits`, and `/api/dialogues/faces` for the preview).
